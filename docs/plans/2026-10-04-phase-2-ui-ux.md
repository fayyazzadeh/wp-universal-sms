# Phase 2 UI/UX Implementation Plan

> **For agentic workers:** Use the host's available task-by-task implementation workflow. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a professional WordPress Admin UI for configuring the SMS gateway, viewing operational status, and inspecting logs without coupling presentation code to SMS transport.

**Architecture:** Add a small admin application layer under `src/Admin`, backed by WordPress options and the existing provider registry/logger contracts. Use WordPress Admin routing, capability checks, nonces, escaped output, and a responsive card-based interface with RTL support. Provider configuration remains definition-driven so later provider presets and the GSM Agent can reuse the same UI boundaries.

**Tech Stack:** PHP 8.1+, WordPress Admin APIs, WordPress Settings API/options, vanilla CSS/JS, PHPUnit.

## Global Constraints

- Keep the SMS core provider-agnostic.
- Do not send SMS from a connection-test action.
- Do not expose API keys, passwords, bearer tokens, or authorization values in logs.
- Use WordPress capability and nonce checks for mutations.
- Keep UI presentation separate from provider transport logic.
- RTL is the default visual direction, with LTR-safe CSS for future localization.
- Phase 2 does not implement licensing or the GSM Agent.
