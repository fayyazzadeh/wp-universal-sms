# WP Universal SMS v0.2.0-beta

## What's New

- Added a real Generic HTTP/REST Provider Configuration screen.
- Added definition-driven HTTP methods and authentication modes.
- Added endpoint, sender, test recipient, timeout, headers, query, JSON body, and response mapping configuration.
- Added a dedicated connection-test endpoint.
- Added secure credential masking and preservation of unchanged credentials.
- Added separate Save Configuration, Test Connection, and Send Test SMS actions.
- Added secure admin action handling through a dedicated AdminActions boundary.
- Added normalized configuration validation through GatewayConfig.
- Added responsive RTL-first provider configuration styling and progressive-enhancement JavaScript.
- Added unit coverage for configuration validation, UI rendering, authorization, connection-test isolation, and test SMS routing.

## Changed

- Plugin bootstrap now delegates admin actions to AdminActions.
- Provider Configuration is now backed by the existing SMS Core/provider abstraction rather than display-only metadata.
- Generic HTTP connection tests reuse configured authentication and common request parameters without falling back to the SMS send endpoint.
- SMSResponse remains compatible with the project's PHP 8.1 minimum.

## Security

- Gateway mutations require manage_options.
- Gateway mutations require a WordPress nonce.
- Credentials are masked in the configuration UI and excluded from safe read models.
- Unchanged masked credentials preserve the stored secret.
- Test Connection never sends an SMS.
- Send Test SMS is explicit and routes through SMS Core.
- Provider response details shown to administrators are normalized and do not intentionally expose credentials.

## Upgrade Notes

Upgrade from 0.1.0-beta is additive. Existing SMS Core and provider contracts remain the integration boundary.

When configuring Generic HTTP/REST, provide a dedicated non-SMS connection endpoint if Test Connection is required.

## Scope Note

This release completes the Provider Configuration portion of Phase 2. It does not mean all Phase 2 roadmap items are complete; operational log persistence, broader integrations, GSM Agent, licensing, and later commercial features remain separate work.
